# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

`cogno-anima` is a modular, infrastructure-agnostic library implementing **Stage 1 (NOUMENO / Perception Layer)** of the Cogno cognitive intelligence pipeline. It normalizes raw user input, detects language, rewrites it into canonical English, measures semantic drift, and extracts structured intent/NER metadata — all decoupled from any proprietary infra (DB, message bus, etc.).

Integration tests use real models and are written to be deterministic (`temperature=0.0`). **CognoBench's default `--model` is `qwen3:8b`** (every local run uses it; `mistral:latest` remains the top ID-bench scorer but is not judge-capable — it approved a wrong execution 3/3).

**The integration suites take a `provider:model` spec, on two axes** (2026-09-06): `COGNO_TEST_MODEL` (NER reads `COGNO_NER_MODEL` first) and `COGNO_TEST_EMBED_MODEL`, the same grammar CognoBench's `--model`/`--embed-model` already use, resolved through `cogno_synapse.create_backend`/`create_embedder` in the ONE place every suite now asks — `tests/integration/backends.py`. Defaults are unchanged: Ollama `qwen3:8b` and `nomic-embed-text:latest`, `temperature=0.0`, `format="json"` on the JSON-consuming ops, and Ollama's own `COGNO_OLLAMA_TIMEOUT` rather than the factory's constant — a unit test compares the built object attribute by attribute against a directly-constructed `OllamaBackend`. Until then every file built its own `OllamaBackend(model=…)`, so the run was **Ollama-only by construction** and this line — which said the suites read `COGNO_TEST_MODEL`, and was true — read as a choice it did not offer: the variable picked WHICH LOCAL MODEL. That is not cosmetic. The served box runs the same `qwen3:8b`, so a run puts every live turn in a queue behind the suite (measured: a host integration run sat 17 minutes on 5 seconds of CPU waiting for Ollama), and there was nowhere else to point it. **The skip travels with the spec** (`backend_unavailable_reason`): the local server for an Ollama spec, the provider's key for a cloud one — a suite pointed at OpenAI that skips itself saying "Ollama is not running" is an instrument lying about why it measured nothing.

The **CognoBench** cognitive benchmark lives in `cognobench/` — see `cognobench/CLAUDE.md` for its design (loaded when working there).

## Architecture

### Pipeline flow

The pipeline operates on a single mutable carrier object, `PipelineContext` (`cogno_anima/types.py`), which flows through stages sequentially:

1. **NOUMENO** (`cogno_anima/stages/noumeno.py`, class `Noumeno`) — perception/normalization:
   - Expands slang via `expand_slangs` (utils)
   - Resolves language by precedence: per-request `ctx.force_language` (the tenant/session language) → stage `default_language` (host/global config, e.g. the SaaS sets `Noumeno(default_language="pt-BR")`) → `langdetect` fallback. The library ships no business default (`default_language=None`); `langue` in NER is inherited from this resolved `noumeno.language`
   - Checks subject continuity against `ctx.metadata["last_rewritten"]` using an `Embedder` (cosine similarity vs `subject_threshold`)
   - Calls the LLM to rewrite input into canonical English, returning JSON (`rewritten`, `context_turn`, `confidence`, `changed`, `preserved_terms`, `rewrite_warnings`)
   - Computes `drift_score` = `1 - cosine(embed(original), embed(rewritten))` and classifies it via `classify_drift()` into `PASS_THROUGH | REWRITTEN | COMPRESSED | EXPANDED | DRIFT` (reconciliation rule: drift > 0.50 forces `changed=True` and tag `DRIFT`)
   - **An embedder failure NEVER kills the turn — and the drift it could not take is `UNKNOWN`, a third state that is neither 0.0 nor 1.0.** Measured in production 2026-09-06: 2 accepted contact messages of 274 (0.73%) over 23.28 h produced no turn at all — no row in `turns`, none in `turn_traces` — both landing under a second past the embedding client's 120 s read timeout while every 200 in the same windows finished under 86 s. The `httpx.ReadTimeout` came out of `_similarity` and crossed `process` untouched. Both call sites now degrade independently (`vocab.EMBED_UNAVAILABLE` on `NoumenoResult.degradations`, a WARNING, `embedding_calls` still counted because the round trip happened): `subject_similarity=None` with `change_subject=False` (assume continuity — the first-turn value, and the conservative side, since `True` DROPS the thread's carry-over), and `drift_score=None` with `drift_tag="UNKNOWN"`, the reconciliation skipped so `changed` keeps what the rewriter itself said. **Why not 0 or 1:** 0.0 reads as *verified, nothing drifted* and waves through a turn nobody checked; 1.0 reads as *total drift*, forces the `DRIFT` tag and can trip a `self_correct` over a turn that was fine. The third way needed no new machinery — `DriftMetrics` already documents `None` as "stage not computed yet (distinct from 0.0 = computed, no drift)" and `compute_cumulative` already renormalized over the non-`None` components; the epistemological one was simply the ONE that could not say it, which is exactly the one an embedder outage destroys. `to_tags()` emits `NOUMENO.DRIFT_UNKNOWN` so a reader of tags alone cannot mistake the absence of `NOUMENO.DRIFT` for a pass. **The line this draws** (and why `generate_json_resilient` still re-raises, deliberately): the LLM **produces** the rewrite the whole pipeline consumes, the embedder only **measures** it — losing the product must be loud, losing a measurement must be recorded AS an absence and never as a value. `asyncio.CancelledError` still unwinds (`except Exception`, not `BaseException`). The ID stage already made this choice (`routing/goal.py` degrades any embedder failure to Jaccard) and so does `cogno_synapse.OllamaEmbedder` in its own docstring.
   - Populates `ctx.noumeno: NoumenoResult`

2. **NER** (`cogno_anima/stages/ner.py`, class `IntentAnalyzer`) — semantic analysis:
   - Requires `ctx.noumeno` to be populated first
   - Builds prompt context from `ctx.noumeno` plus carry-over metadata (`last_goal`, `last_pii_risk`, `active_domains`, `turn_number`); if `noumeno.change_subject` is true, prior context is dropped
   - Calls the LLM and parses/sanitizes the JSON response into an `IntentResult` — every field is validated/coerced against a fixed vocabulary (`VALID_INTENTS`, `VALID_SENTIMENTS`, `VALID_TEMPORAL`, `VALID_TRIAD`, `VALID_MODALITY`, `VALID_SPEECH_ACTS`, `VALID_PAROLE`, `NER_KNOWLEDGE_DOMAINS`, etc.), with fallback heuristics when the LLM omits/garbles fields (e.g., `intent_class=UNKNOWN` falls back based on `mandatory_tags`; empty `domains` falls back from `mandatory_tags` via `_TAG_TO_DOMAIN`)
   - PII detection: raw `pii` strings are normalized/aliased (`security/pii.py: normalize_pii_types`) and risk is computed deterministically (`compute_pii_risk`) — never trust the LLM's own risk judgment
   - Populates `ctx.intent: IntentResult`

3. **ID** (`cogno_anima/stages/id.py`, class `IDStage`) — strategic router & continuity:
   - Requires `ctx.intent` (and `ctx.noumeno`) to be populated first. **Heuristic — no LLM**; signature is `process(ctx, embedder)` (the embedder is used only for goal similarity).
   - **Stateless across turns:** all cross-turn state rides in `ctx.metadata["id_state"]` (a serializable dict the *host* persists to its DB/Redis) — there is no live per-session instance, so it survives a multi-worker HTTP setup. `turn_number` comes from `ctx.metadata["turn_number"]` (host authoritative) or auto-increments from `id_state` when absent.
   - Composes three pure helpers in `cogno_anima/routing/`: `GoalManager` (goal continuity NEW→ONGOING→COMPLETED→ABANDONED via staged checks: CLARIFICATION → domain match → anaphoric-PII → `context_dependent` → semantic cosine with **one-sided enrichment**, Jaccard fallback; `update()` returns `(status, goal, similarity)`), `IntentionTracker` (BDI intentions, max 5, FIFO), `AttentionFilter` (additive scoring over host-injected `ctx.metadata["attention_candidates"]`). **The staged order reads as "fast paths, then the real semantic comparison" and that is backwards: the fast paths ARE the mechanism.** Measured 2026-08-19 over the 14 labelled pairs of `cognobench/id_cases.py` — under the shipped embedder the 0.75 threshold is reached by 1 of 14, and no cut beats answering ONGOING every time (the ONGOING and ABANDONED distributions OVERLAP, on both the goal-text and the raw-turn signal). Stage 2 is a TIE-BREAKER, not the gate; the threshold is not a knob to tune, and two auto-invalidating tests in `test_goal_manager.py` fail the day that stops being true. Believing the shape cost one already: removing the Stage 1 catch-all match looked like tightening a lax fast path and instead pulled the prop out — `long_chain` lost its goal three turns running.
   - Routing priority (`_resolve_route`): `pii_risk=CRITICAL`→SUPEREGO (`blocked=True`) → `HIGH`→SUPEREGO → `emotional_override`→SUPEREGO → `CREATIVE_TASK`→SUPEREGO → `ACTION_REQUEST`/`INFORMATION_REQUEST`→EGO → `SOCIAL`→SUPEREGO → trust `triad_signal` → `BALANCED`. The EGO is the **tool gateway**: both action *and* information requests route to it (it no-ops to a draft when no tool is needed) — widened from the old `ACTION+SYSTEM` rule, which starved tool-requiring info queries ("what's my balance?"); surfaced by the e2e conversation simulation.
   - Cross-turn signals: temporal stickiness (a follow-up under an ONGOING goal keeps the prior turn's higher temporal — recorded on `IdResult.temporal_class`, **does not mutate the `IntentResult`**); `emotional_override` from a `frustration_streak` counter (≥ threshold of consecutive `FRUSTRATED` turns; host may inject its own); `complexity` (advisory `LOW|MEDIUM|HIGH|EXPERT`; `complex_domains` configurable, core default none — the core never escalates models); `needs_confirmation` (`_needs_confirmation`) — flags an ACTION the *user* framed tentatively (`speech_act=INTERROGATIVE` or `modality∈{POSSIBLE,UNCERTAIN}`; `INFORMATION_REQUEST` never flags). **SIGNAL ONLY** — the ID never touches `ego_readonly`; the host decides (ask directly, or route to the EGO read-only — see EGO gate A). Two more **signal-only** doubt flags (host decides): `confidence_divergence` (`|noumeno.confidence − intent.confidence| ≥ threshold`, default 0.4 — the *disagreement* between stages is the robust signal, not the absolute LLM confidence the core otherwise distrusts) and `clarification_suggested` (the NOUMENO rewriter raised `rewrite_warnings`).
   - Feeds drift: seeds `ctx.drift` if absent, then `compute_situational(goal_similarity)` → `compute_cumulative()` → `downgrade_for_intentional_shift(goal_status)`. Records embedding cost (from the goal-similarity calls, via a usage-aware closure) in `StageMetrics(model="heuristic")`; tokens are 0 on fast-paths/first turn.
   - Output (`triad_route`/`goal_status`/`complexity`) is sanitized against the closed vocab (`VALID_TRIAD`, `VALID_GOAL_STATUS`, `VALID_COMPLEXITY`). Populates `ctx.id_result: IdResult`.
   - **Out of scope (host/EGO):** persona↔MCP binding, skill selection/execution, model-ladder escalation, session splitting, and the dynamic `ask_user` text — the ID emits signals (`drift_action`, `blocked`, `complexity`), the host decides.

4. **EGO** (`cogno_anima/stages/ego.py`, class `EgoStage`) — executor & tool dispatch:
   - Requires `ctx.noumeno` + `ctx.intent`. Signature is `process(ctx, backend, dispatcher, *, system_prompt)` — `backend: LLMBackend`, `dispatcher: ToolDispatcher` (host-injected), `system_prompt` is the persona's **execution** prompt (host).
   - **EGO = executor, SUPEREGO = locutor.** The EGO runs an agent loop (decide tool → `dispatcher.execute` → feed result back → repeat) and gathers data; it does **NOT** write the user reply. `EgoResult` is a trace (`steps` = source of truth; `tools_executed`/`draft`/`has_side_effects` derived) + a `draft` (the model's last text) for the SUPEREGO to voice. There is no `response`/`response_source` and no `returns_raw_json` (presentation left the EGO).
   - **NER signal enrichment in `_task_context`** (prompt hints): user `intent.constraints` / `intent.negation` are surfaced as `Constraints (must respect)` / `Must NOT` so the loop honors explicit restrictions. Two course-correction hints ride the same block: a deteriorating `intent.sentiment` (the contact is losing patience) and `ctx.metadata["circling_streak"]` — a HOST-counted number of consecutive turns its anti-repeat guard had to act on, which from `EgoStage.CIRCLING_MIN` (2, overridable; 0 disables) tells the executor it keeps arriving at the same answer. The host must recompute the streak every turn (a stale one warns forever), and an unusable value degrades to 0 rather than raising — a prompt hint must never abort a turn.
   - **Three confirmation gates (capability, not prompt-hints — `docs/ACT_CONFIRM_READONLY.md`).** Tool classification is host-declared via the optional `ToolPolicyDispatcher` Protocol (`is_mutating`/`requires_confirmation`, probed with `isinstance` like `ToolCallingBackend`); the core never hardcodes which tools mutate. **(A) Read-only mask** — when the host sets `ctx.metadata["ego_readonly"]` (acting on the ID's `needs_confirmation` signal because the *user* was tentative), the EGO offers ONLY non-mutating tools and `force_first` is off → it consults + proposes, never commits. **Fail-safe:** no policy → mask ALL tools (propose via draft). **(B) Confirmation gate** — a `requires_confirmation` (destructive) tool the model picks is **never executed** without `ctx.metadata["ego_confirmed"]`; the core holds it, records `EgoResult.pending_confirmation`, and stops to propose (the host runs its confirm UX → next turn with `ego_confirmed` → executes). **Opt-in** (no policy → no gate). **(C) The SKILL asks** — a `ToolResult(needs_confirmation=True)` says the skill RAN, decided it must not commit, and is asking about THIS call: the EGO records it as pending and stops, exactly like B, and the proposal text is the skill's own `output`, grounded in what it just read. It exists because B is per tool NAME and decided BEFORE execution, so it cannot know that cancelling *this* appointment is two hours away, or that *this* entry is a hundred times the usual one — the skill knows, because it read. A `True` is a **promise that nothing was committed**: the call is recorded `ok=False`, so `committed_this_turn` (which needs `ok` AND `side_effect`) can never count a proposal as a write, however the skill fills the other fields. The confirmation reaches the skill through the channel the host already owns (the skill's own context/metadata — `cogno_cortex.ToolContext`); **the core never invents an argument name**, because what a skill needs in order to commit is the skill's business. A confirmed call whose skill STILL asks committed nothing and there is nobody left to ask, so `_refuse_if_still_asking` fails it LOUDLY (`ok=False`, named error) rather than shipping "done" over a turn that wrote nothing — applied on BOTH routes a confirmed call arrives by (the deterministic replay and the model re-issuing inside the loop), because the first cut guarded only the replay and the loop counted the proposal as a commit. **A retenção de B e C é por CHAMADA, não por turno** — ela para o LAÇO, não o PASSO: um passo com duas chamadas segura a que pediu e executa a irmã, então o turno pode dizer "estou a segurar" e "comitei" ao mesmo tempo. Comportamento herdado (medido idêntico no gate B), mas a fonte C alarga o ALCANCE: o B só dispara em tool que o host declarou destrutiva, o C pode ser levantado por qualquer skill em qualquer chamada. A is broad (user unsure → mask all writes), B is surgical (dangerous tool → hold that call), C is specific (this call, on this data → propose); all three are propose/commit, all three keep "core signals, host decides". **C supersedes the ID's `needs_confirmation` in practice:** that one guesses from how the user PHRASED the request and has no reader; this one is a fact about what the skill found. **How long a hold LIVES is the host's, and the two-turn drawing is a shape, not a promise that the answer comes next** — a hold is `EgoResult.pending_confirmation` for exactly one turn, and only a host stamping `ego_confirmed` makes it survive. Measured in `cogno-host` 2026-09-05: a proposal, one unrelated question, then "sim" — the session state was rebuilt each turn, nothing was held by the third message, and the model answered "Vou agendar…" with zero tool calls. The property a host may not break, now written where the gates are (`docs/ACT_CONFIRM_READONLY.md`): **nothing is executed that was not re-proposed to the contact** — carrying a hold across turns without that rule trades "the proposal is forgotten" for "an ambiguous yes commits", which is the worse of the two.
   - **Dual-path FC:** a backend satisfying `ToolCallingBackend` (separate optional `Protocol` in `llm/base.py`, NOT folded into `LLMBackend`) uses native function calling; a plain `LLMBackend` (a stub, the distilled student, the default `OllamaBackend`) uses the **text-fallback path** — the model emits `<TOOL_CALL>` tags read by `parse_tool_calls_from_text` (`llm/tool_parsing.py`, ported from the parent; also rescues FC leaks). On fallback the tool list + `<TOOL_CALL>` mechanics are rendered into the prompt; on native they travel via the API.
   - **Execution is delegated** ("EGO = brain, dispatcher = hands"): the core never touches the DB/MCP/API, so atomicity/rollback/outbox are **host** concerns. `ToolResult` (`output, ok, error, side_effect`) carries no `compensating_tool` (compensation is host-internal). Error contract: recoverable failure (`ToolResult(ok=False)`) is fed back so the model self-corrects; fatal (`MCPDispatchError` raised by the dispatcher) propagates; a stray exception is wrapped in `ToolExecutionError` and propagated (the EGO never guesses recoverability).
   - **Loop policy:** `max_steps = ctx.metadata.get("ego_max_steps", default)` where `default` is 5, or 8 when `intent.is_composite` (a multi-task request gets more budget; the host's explicit `ego_max_steps` always wins); `intent.is_sequential` adds an **ordering instruction** + the `causal_chain` as a numbered supporting plan in the task context (the loop still decides real tool order). Stop when the model emits no tool_calls (→ `draft`); `tool_choice="required"` on the 1st iteration for `ACTION_REQUEST`; hallucinated tool name → recoverable feed-back; **duplicate-call detection** (ported from parent: same `(tool,args)` blocked after 2 repeats, abort after 2 all-blocked steps). Budget/convergence bounds are **signals** (`interrupted=True` + partial result), not exceptions. Correction loop (host-orchestrated EGO↔SUPEREGO): `ctx.metadata["ego_correction"]={reason,attempt}` drives an `[ACTIONS ALREADY EXECUTED]` block built from the prior `ctx.ego_result`; the core renders whatever trace the host hands back (host rollback → empty trace → fresh retry).
   - Tokens summed across the loop into one `StageMetrics(model=backend.model)` (embeddings 0); folded into `PipelineContext` totals via `ctx.ego_result` + `ego_metrics` (like `id_metrics`). **Out of scope (host):** persona/MCP/skill-selection/RBAC, KG/history retrieval, mobile brevity + voicing (SUPEREGO), model-ladder, atomicity. A standalone embedding `ToolRetriever` for large catalogs is left to the host (the EGO trusts `dispatcher.tools_schema()` as final). When a persona draws tools from several sources at once (in-process skills via `cogno-cortex`, an MCP client, host-native functions), the host merges them with `cogno_anima.tools.CompositeDispatcher` — a `ToolDispatcher` (+`ToolPolicyDispatcher`) whose `tools_schema()` is the union (first source wins on a name collision) and whose `execute()`/policy methods route to the owning source (a non-policy source is treated conservatively: assumed mutating, no confirmation gate). The EGO still sees one flat tool set; the *contract* is the unifier — skill/MCP/native are just sources behind it. **The router also forwards `source_requires_confirmation`** — *did the SOURCE itself declare this destructive*, as opposed to *it is a write and nobody exempted it*, which `requires_confirmation` flattens together. A host layering a blanket "every unexempted write confirms" rule over each source exposes the finer predicate on its wrapper, and a caller above the router (an anti-holding floor, say) needs the two apart. The fallbacks follow the SAME conservative convention as the two methods beside it: the finer predicate when the source has it; otherwise a policy source's own `requires_confirmation` **is** the source verdict (answering `False` there would waive a tool the source really did mark destructive); a non-policy source declared nothing. **This was measured, not designed:** the router defined neither the method nor `__getattr__`, so a host floor reaching for it through the wrappers hit this class and fell back to holding — and a contact who asked for a human was answered "shall I proceed?" instead of being transferred. A generic `__getattr__` forwards everything a WRAPPER does not mediate (one layer, one source) and is the wrong answer for a ROUTER over many: it cannot know which source to forward to. It is **also** the wrong answer for the two POLICY methods even on a wrapper — Python 3.12 resolves `runtime_checkable` protocol members with `inspect.getattr_static`, which never calls `__getattr__`, so the wrapper vanishes from the probe and the confirmation gate stops firing entirely. Those bind onto the INSTANCE, conditionally, via `cogno_anima.tools.bind_delegated` (below).

5. **SUPEREGO** (`cogno_anima/stages/superego.py`, class `SuperegoStage`) — guardrails, judge & voicer:
   - **EGO=executor, SUPEREGO=locutor:** the SUPEREGO **writes** the final user response from the EGO's gathered data (it does NOT review a pre-written one — that is the key divergence from the parent). Three LLM ops, **A2** (host injects a backend per op, may differ — e.g. big judge + small voicer, or the same model):
     - `check_input_scope(ctx, backend, *, scope_prompt) -> ScopeCheckResult` — pre-EGO cheap ALLOW/BLOCK relevance guard; NER-assisted bypass for SOCIAL/CLARIFICATION (no LLM call); **fail-OPEN** (a cost guard must never refuse a legit user on error); the `refusal_message` is generated in the same call.
     - `evaluate(ctx, backend, *, limits_prompt) -> SuperegoResult` — the **JUDGE**: approve the EGO execution or return a `critique`. **Criterion #1 is goal↔execution** ("asked X, did X not Y"), then **#2 user constraints** (honored every `intent.constraints`, did NOT do what `intent.negation` forbade — rendered into the prompt via `_format_restrictions`), then completeness, grounding (incl. NOUMENO `preserved_terms` reproduced exactly — `_format_preserved`), safety/limits. **Fail-CLOSED** (never approve unverified — a false-pass is worse than a retry). The `critique` feeds the EGO's `ctx.metadata["ego_correction"].reason` (the correction loop closes). **Conversational turns swap the criteria:** a persona with no tools executes nothing *by design*, so criteria #1/#3 are unsatisfiable — measured live, the judge rejected 100% of turns (52/0 across 12), including correct ones, and the retry loop then shipped a handoff message instead of the answer. The host sets `mk.JUDGE_CONVERSATIONAL` (it is the only layer that knows whether a tool was offered) and `_build_judge_prompt` selects `_CONVERSATIONAL_CRITERIA`: TRUTH first (incl. preserved terms), constraints, ANSWERS (admitting a limit IS a complete answer; a follow-up question is correct when the user asked nothing), safety/limits. Truth and limits are never relaxed. **A third valid outcome joined them on 2026-08-19: NOTHING TO DO.** When the reads show the request is already satisfied (everything already confirmed, the list empty) and the draft says so truthfully, there is no write to make and the absence of one is CORRECT — a fail-CLOSED judge was reading it as an incomplete goal. Measured on `doctor_confirm_all_when_none_pending`: it rejected the correct execution twice with CONTRADICTORY critiques (first for listing the rows, then for not listing them) and the retry loop exhausted into a handoff; 0/3 → 3/3 with the clause, fabrication controls unmoved at 0/3. The no-op tool result ("was ALREADY CONFIRMED — no change was made") is named explicitly in the criteria: it exists to tell the MODEL it acted on a stale id, and the judge was reading it as proof of failure. The same signal also suppresses the EGO's `tool_choice="required"` (forcing a call would pick an escape hatch), and `voice` renders a *second* rejection variant when the orchestrator reports `voice_correction.kind="unverified_claim"`: the refused draft is UNVERIFIED CONTENT and must be dropped, not re-voiced (the old wording spoke only of ACTIONS, so on a no-tool turn the rule was obeyed trivially and the refused claim shipped verbatim). **A fourth joined on 2026-09-03: OUT OF REACH — and it is the only one that is CONDITIONAL.** When the honest reply is "I cannot do that here", criteria #1 and #3 are unsatisfiable for the same reason they are on a conversational turn: there was no tool to run, so no execution could have met the goal and no retry can produce one. The clause that says so was already written — inside `_CONVERSATIONAL_CRITERIA`, a branch a persona WITH tools never reaches — so it is now one shared constant (`_ADMITTING_A_LIMIT`, read by both) and the execution branch gets `_OUT_OF_REACH` around it. The opening travels WITH its evidence: `_OUT_OF_REACH` renders only when `_format_unavailable` produced a `# NOT AVAILABLE this turn` block, because without it the judge cannot tell "there was no tool" from "there was a tool and it went unused" — both render as `(no tools executed)`, and only one of them makes "I can't do that" honest; a turn with no block is judged byte for byte as before. Measured live on the scheduling hub (tools present, therefore never conversational): the honest draft was rejected 3/3 with both critiques citing exactly those two criteria and the retry loop shipped the exhaustion handoff, while the SAME turn one tree earlier with a FABRICATED draft was approved at the FIRST attempt. ### Tool dispatch adapters (`cogno_anima/tools/`)

`ToolDispatcher`/`ToolPolicyDispatcher` (`tools/base.py`) is the contract; `CompositeDispatcher`
(`tools/composite.py`) is the ROUTER that unions many sources behind it. The rest of the package is
the **wrapper** side of the same contract — the generic, business-free adapters a host stacks around
the composed dispatcher. They were written in the host, one per live incident, and moved here
because a wrapper that implements this protocol belongs beside the protocol: each one is a rule
that every wrapper author was otherwise re-deriving alone, and the hand-written copies are the ones
that failed. **What did NOT move is every policy that names a tool** — which writes ask before they
commit, which are exempt, which roles see what, which ids are guarded. That is the host's catalog
and its business; the core ships the mechanism and takes the declaration as a parameter.

- **`bind_delegated(wrapper, inner, *members)`** (`tools/binding.py`) — bind DELEGATED protocol
  members onto the INSTANCE, conditionally, so `isinstance(x, ToolPolicyDispatcher)` keeps telling
  the truth about the source underneath. Three shapes fail and this is the one that does not:
  `__getattr__` alone is invisible to Python 3.12's `getattr_static` (the wrapper leaves the probe
  and gate B silently stops firing); declaring on the class LIES for a source with no policy (a
  safety wrapper arming a gate over guesses); `__slots__` is the same lie with a descriptor, and it
  reads True on 3.10 **and** 3.12 — the older, quieter trap, only ever hidden by `__getattr__`
  failing the other way first. A member the wrapper's own class defines is never overwritten, so a
  wrapper that TIGHTENS `requires_confirmation` cannot be disarmed by forwarding the inner's.
- **`CommitRecordingDispatcher` + `new_sink()`/`committed()`** (`tools/commit_sink.py`) — records a
  turn's commit (`ok` AND `side_effect`, the same pair `committed_this_turn` requires) into a
  container the CALLER pre-placed. Two facts make the shape: a turn's metadata is copied shallowly on
  the way in, so a pre-placed object is the same object all the way down while a key stamped from
  inside never comes back **and fails silently**; and the record has to land in `execute`, not in a
  post-turn hook, because the branch it exists for is "attempt 1 wrote, a later stage raised" — the
  branch where a hook after the loop never fires at all.
- **`ConfirmArgumentRecordingDispatcher` + `call_key`/`held_calls`** (`tools/confirm_args.py`) — the
  RETURN half of the EGO's gate C. A tool that asks about THIS call names what it needs back; the
  recorder captures it keyed by `(tool, arguments)` (so a step with two proposals keeps them apart)
  and `held_calls` merges it into the replay, **only ever ADDING** — the proposal named a row and the
  commit must be that row. Read duck-typed off a `confirm_arguments` attribute that `ToolResult`
  deliberately does not declare: what a skill needs in order to commit is the skill's business, so the
  carrier belongs to the bridge (`cogno_mcp.MCPToolResult`). `held_calls`' keyword has no default on
  purpose — forgetting the return trip is otherwise invisible until production.
- **`IdProvenanceDispatcher`** (`tools/id_provenance.py`) — refuses (recoverably) a guarded write
  whose id did not appear in a successful read EARLIER IN THE SAME TURN, so a stale id recalled from
  an old session's memories cannot reach a write. `guarded` (`tool → (id argument, the READ that
  legitimises it)`) is INJECTED with no default: which tools carry ids, and which read names them, is
  the caller's catalog — and the read tool is part of the REFUSAL, so naming one the persona does not
  have turns a self-correction into a loop. Build a fresh instance per turn.

The two recorders bind their policy conditionally (they add no verdict of their own, so claiming one
would be a lie about the source); the provenance guard and the router DECLARE it, answering the EGO's
own fail-safe defaults, because both must answer on behalf of a source that may have none.
`tests/unit/test_protocol_probe_contract.py` derives the wrapper list from the package and fails a new
wrapper that arrives without the binding — the rule is pinned by mechanism, not by a hand-written list.

### LLM/Embedder abstraction — extracted to **`cogno-synapse`**

The model-transport layer (formerly `cogno_anima/llm/`) was **extracted into the sibling `cogno-synapse` lib** (`cogno_synapse` package; repo `/home/vinicius/git/cogno-synapse`). `cogno-anima` now declares `cogno-synapse` as a runtime dependency and imports the protocols/backends from it (`from cogno_synapse import LLMBackend, OllamaBackend, …`). For backward compatibility the top-level `cogno_anima` package **re-exports** the same names (`from cogno_anima import OllamaBackend` still works), and `cogno_anima.errors` re-exports `InvalidAPIKeyError`/`MissingAPIKeyError` (now `cogno_synapse.SynapseError` subclasses, no longer `CognoError`). Resilience (`FallbackBackend`) runs over the `cogno-homeo` kernel — see below.

`cogno_synapse/base.py` defines three `Protocol`s (runtime-checkable, structurally typed — no inheritance required):
- `LLMBackend`: `async generate(system, prompt) -> (text, tokens_in, tokens_out)`, plus a `model` attribute
- `ToolCallingBackend` (extends `LLMBackend`): adds `async chat_with_tools(messages, tools, tool_choice) -> (message_dict, tin, tout)` + `supports_native_tools()` for native function calling. **Optional and separate** so a text-only backend (a stub, the distilled student) satisfies only `LLMBackend` and the EGO auto-uses the text-fallback path (`isinstance(backend, ToolCallingBackend)`); NOUMENO/NER/ID never touch it.
- `Embedder`: `async embed(text) -> list[float]`, `async similarity(a, b) -> float`

`cogno_synapse/ollama.py` provides concrete implementations (`OllamaBackend`, `OllamaEmbedder`), talking to a local Ollama server over `httpx`. `OllamaBackend` sends `think=false` by default: reasoning models (qwen3, deepseek, …) otherwise route their output to a separate `thinking` field and leave `response` empty, which would make the JSON stages raise `StageParseError`; the cognitive stages want direct JSON, not chain-of-thought (`generate()` also falls back to `thinking` if `response` is empty). Set `OllamaBackend(..., think=True)` to opt back in. `OllamaEmbedder` is a thin, stateless client; it also exposes `embed_with_usage`/`similarity_with_usage` returning `(vector, tokens)` (from Ollama's `prompt_eval_count`). Caching is **backend-agnostic**: `cogno_synapse/cache.py: CachingEmbedder` wraps *any* `Embedder` to add a bounded LRU cache (by lowercased text) plus token/call accounting (`EmbeddingUsage`) — e.g. `CachingEmbedder(OllamaEmbedder(...))`. New backends implement the same protocol shape and get caching for free by composition — stages depend only on the protocol, not on Ollama.

**Cloud backends** (`cogno_synapse/{openai,anthropic,groq,gemini,bedrock}_backend.py`): adapted from the parent — each implements `LLMBackend` + `ToolCallingBackend` (`generate` + `chat_with_tools` converting the unified OpenAI-format messages/tools to the provider's shape + `supports_native_tools`). **SDKs are lazy-imported** (optional extras: `pip install "cogno-synapse[openai|anthropic|groq|gemini|bedrock|llm]"`; the convenience extra `cogno-anima[llm]` pulls `cogno-synapse[llm]`). Two deliberate divergences from the parent: (1) **errors propagate** — they **raise** on transport/auth failure (`InvalidAPIKeyError` for 401/403) instead of returning `("",0,0)`, matching the core contract; (2) **no tenant-key contextvar** (host owns key rotation). `cogno_synapse/fallback.py: FallbackBackend` is a slim, infra-agnostic failover chain (try each, first success wins, last error propagates; skips non-FC backends for `chat_with_tools`) whose loop now runs over `cogno_homeo.resilient_call`, so a host can opt into a circuit breaker / retry / metrics by passing them to the constructor — with none supplied it behaves exactly as before (the parent's Redis circuit-breaker + probe threads remain host concerns and were NOT ported). `cogno_synapse/factory.py: create_backend("provider:model")` instantiates a single backend (raises `MissingAPIKeyError` for a cloud provider without a key); the business `_FALLBACK_MATRIX` (model ladders) is host, not core. **OpenAI-compatible providers** (DeepSeek, Moonshot/Kimi, xAI/Grok, OpenRouter, Together, Fireworks) reuse `OpenAIBackend` via its `base_url` param instead of a class each — the factory's `_OPENAI_COMPATIBLE` registry maps each prefix to `(base_url, key_env)`, e.g. `create_backend("deepseek:deepseek-chat")`. There is deliberately **no `mistral:` prefix** (it would clobber Ollama's `mistral:latest`, the default local model). Unit tests mock the SDK clients (no network); integration tests are gated on real keys (auto-skip). All of these tests live in the `cogno-synapse` repo now.

### Prompts

Prompt templates live under `cogno_anima/prompt_templates/<stage>/` (`noumeno/`, `ner/`) as plain text files, loaded via `cogno_anima.prompts.load_prompt(stage, prompt_name, prompts_dir=...)`. The loader strips YAML frontmatter (`---\n...\n---\n`) and any `TODO(docs)` lines. `IntentAnalyzer` can load an alternate system prompt via `system_prompt_name` (default `system.txt`); the default NER prompt is concise (~3.4k tokens) so it fits Ollama's default `num_ctx=8192` with room for input/output.

The `domains` closed list inside `cogno_anima/prompt_templates/ner/system.txt` is the source of truth and **must stay byte-for-byte aligned with `NER_KNOWLEDGE_DOMAINS` in `cogno_anima/stages/ner.py`** — `tests/unit/test_pipeline.py::test_code_domains_match_prompt_domains_exactly` enforces this. `langue` is no longer detected by the LLM; the NER inherits it from `noumeno.language`.

**`committed_this_turn(ctx)` — one definition, one enumeration.** "Did this turn run a mutating tool successfully, on ANY attempt?" It reads the turn's own two execution lists — `ctx.turn_executions` (the accumulator) and `ego_result.tools_executed` (a FLOOR, for a single-shot pipeline), in UNION since #105 and no longer "first non-empty wins" — plus `ctx.consult_result` and `metadata[mk.PRIOR_ATTEMPT_COMMITTED]`. **`consult_result` is the intra-turn CONSULT**: a hub persona asks a specialist mid-turn and consolidates her answer, so the tools SHE ran are this turn's tools, and a predicate blind to them answers "repeating is safe" over a turn that already committed. It enters the walk the whole family shares (`types._any_execution`), so `wrote_for_the_contact` and `write_attempted_this_turn` gained it in the same edit — a source only one of them reads is the defect that walk exists to prevent. It is an `Optional[EgoResult]` and not a list because `None` (**nobody was consulted**) and an empty trace (**a specialist was consulted and executed nothing**) are opposite facts for the judge; the consult is ADDITIVE and stays out of `_any_execution`'s `unreadable` denominator, which asks only whether the turn's OWN record could be read (a second executor's clean trace cannot vouch for a hub record nobody could read, and the union's rule is that a new source can only turn False into True). Cost rides on `retry_metrics`, not on a sixth stage slot. The third exists because the first two live ON the context and can die together: in the host's model-routing fallback, attempt 1 commits and a LATER stage raises, and the exception takes the context and its record with it, so the retry is a fresh turn where the write is nowhere. There only the host knows, so it declares — TRUE-only, and the declaration ADDS to what the trace shows, never replaces it. **Who calls it is enumerated ONCE, in the `committed_this_turn` docstring** (`cogno_anima/types.py`) — count, files and functions. This file used to repeat that list and `metakeys.py` repeated it again; four consecutive PRs (#115–#118) each corrected the NUMBER in the copies and each left a stale sub-count or a missing name behind, because a test can pin a token and cannot read two hundred words of prose. The copies are now pointers, and `cogno-host` asserts that every calling function is NAMED in that one docstring. **Why it matters here:** a rule each consumer re-derives is a rule each consumer gets wrong alone — that is what the third source exists to prevent, and what the two VOICE policies proved by arriving already re-deriving it (they read `ego_result.has_side_effects`, the SURVIVING attempt, so a turn that booked, was judge-rejected and re-voiced without tools reported "nothing was written" about a turn that wrote). The last layer that re-derived it closed on 2026-08-25: the offline promise auditor now reads the `trace["guards"]["committed"]` stamp — which the host writes by CALLING this predicate — in union with the execution lists, which stay as a FLOOR because a degraded readout stamps `False` and the declaration is TRUE-only.

### Models (`cogno_anima/types.py`)

All cross-stage data is `pydantic.BaseModel`. Key types: `StageMetrics` (per-call telemetry; carries LLM `tokens_in`/`tokens_out` **and** `embedding_tokens`/`embedding_calls` **and** `cached_tokens`; `tokens_total` auto-computed in `model_post_init` as `tokens_in + tokens_out + embedding_tokens` — `cached_tokens` is deliberately absent from that sum, being the SUBSET of `tokens_in` the provider served from its own prompt cache, read through `cogno_synapse.cached_tokens_of` immediately after the `await` that produced the call and summed on the same axis as the tokens beside it: per attempt in NOUMENO/NER, per step in the EGO loop, per call in the SUPEREGO. A backend that reports nothing gives 0, which downstream is the FULL input rate — today's behaviour), `NoumenoResult`, `IntentResult` (with helper methods `aristo_tag`/`aristo_desc`/`aristo_parsed` for parsing `"TAG | description"`-style aristotelian fields), `IdResult` (ID routing/continuity output: `triad_route`, `active_goal`, `goal_status`, `goal_similarity`, `active_intentions`, `attention_focus`, `blocked`/`block_reason`, `turn_number`, `temporal_class`, `emotional_override`, `complexity`, `metrics`), `DriftMetrics`, and `PipelineContext` (the carrier — `noumeno`/`intent`/`id_result`/`ego_result`/`consult_result`/`drift` — with derived properties `total_tokens` (incl. embeddings), `total_llm_tokens`, `total_embedding_tokens`, `total_elapsed_ms`, `stage_metrics`, and per-stage `noumeno_metrics`/`ner_metrics`/`id_metrics`). NOUMENO records embedding cost from its similarity calls; NER records its LLM generate tokens; ID records embedding cost from goal similarity (no LLM tokens).

### Testing conventions

- `tests/conftest.py` provides `StubBackend` and `StubEmbedder` fixtures (`stub_backend`, `stub_embedder`) — zero-network test doubles for unit tests.
- `tests/unit/` — pure unit tests using stubs, no network.
- `tests/integration/` — real Ollama-backed tests; check `is_ollama_available()` and skip if unreachable. Always use `temperature=0.0` — it buys determinism against the local default (measured: zero unstable checks over three cognobench sweeps on qwen3:8b) but only REQUESTS greedy decoding from a hosted provider, which nothing obliges to deliver it; a suite pointed at one via `COGNO_TEST_MODEL` is sampling. See `BENCHMARKS.md` § *Reading a number from this bench*.
- Async tests use `@pytest.mark.asyncio`.

### Language conventions

All docstrings, comments, identifiers, prompts, and documentation are in **English** — the project's canonical language for its open-source audience. The one deliberate exception is **Portuguese domain data** that must stay Portuguese to function: e.g. the PT/ES pronoun map and slang dictionary, the birth-context regex in `security/pii.py`, and Portuguese user-input fixtures in `tests/`/`cognobench/` (they are the input under test for the PT→English rewrite — translating them would defeat the test). English comments may quote a Portuguese example string to illustrate such input. (Historically stage-logic comments were written in Portuguese; that convention was retired — do not add new Portuguese prose.)
