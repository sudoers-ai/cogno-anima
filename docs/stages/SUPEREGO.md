# SUPEREGO — guardrails, judge and voice (the stage as a whole)

Moved verbatim from `CLAUDE.md` on 2026-11-08: the contract did not change. `CLAUDE.md` keeps a short summary and points here. Update this file in the same pull request as any change to the SUPEREGO stage as a whole, the verdict reader or the stop reasons, as `CLAUDE.md` used to be updated.

5. **SUPEREGO** (`cogno_anima/stages/superego.py`, class `SuperegoStage`) — guardrails, judge & voicer:
   - **EGO=executor, SUPEREGO=locutor:** the SUPEREGO **writes** the final user response from the EGO's gathered data (it does NOT review a pre-written one — that is the key divergence from the parent). Three LLM ops, **A2** (host injects a backend per op, may differ — e.g. big judge + small voicer, or the same model):

- **Only a JSON boolean is a verdict (2026-10-07, 0.1.3, `cogno_anima/verdict.py`).** The judge read its verdict with `bool(data.get("approved", False))` and the guard with `bool(data.get("blocked", False))`, and a non-empty string is truthy: `{"approved": "false"}` APPROVED the execution the reply rejected (a fail-CLOSED gate failing open), `{"blocked": "false"}` BLOCKED the contact the classifier allowed, and a guard reply with no JSON in it was an ALLOW whose record was byte for byte that of a real one. Found by reading, then measured on `b05e9c8` with a stub backend (the red twins are `tests/unit/test_verdict_red_twins.py`, which imports nothing the fix added so that it RUNS on the old tree: 4 failed there). `read_verdict(raw, key)` is the ONE strict reader, for the judge, the guard and `ProposalJudge` (which was the precedent and still read the LAST of two keys): a string, a number, `null`, a list, a missing key, the key written TWICE (`object_pairs_hook` sees the pairs before `json.loads` collapses them; only the verdict key and only the top level are refused) or no JSON object is an ERROR named from the closed `VALID_VERDICT_READS` (`boolean | string_bool | not_boolean | missing | duplicated | unparseable`, plus `call_failed`, which only a stage records). **What an error does is each stage's contract and is not decided in the reader:** the judge fails CLOSED with the exported constant `UNREADABLE_VERDICT_CRITIQUE` and uses nothing of the unread reply (its critique included); the guard fails OPEN and is MARKED; the pre-judge answers `error`. **The mark is the point** — `SuperegoResult.verdict_read`, `ScopeCheckResult.verdict_read` and `ctx.metadata[mk.SCOPE_VERDICT_READ]` (per-turn, popped on a bypass like `SCOPE_PROMPT_SHA`; `""`/absent = no verdict was ASKED): the raw reply is persisted nowhere, so the past is not countable (the one indirect signal, the judge's default critique, gave 0 in 916 ledger rows on a downstream host and says nothing about strings). **Two costs, declared:** a string `"true"` is not a verdict either, so a model that spells booleans as strings is rejected on every turn and never blocks; and `evaluate` asks ONCE — it does not re-ask — so an unreadable verdict costs the correction loop what a rejection costs (budget 1 → `judge_exhausted`; budget 2 → the EXECUTOR re-run over a critique that names no defect; two-tier → the strong judge reads it in the same attempt, where it used to be a final approval). Re-asking the judge instead is the better repair and was deliberately left out: it changes the call count and the rate has never been measured. `SuperegoStage._parse_json` is the TOLERANT read over the same extractor (`verdict.parse_object`) and has one caller left, the selector, which reads two lists and no boolean; `tests/unit/test_verdict_is_a_json_boolean.py` derives the callers of both readers from the AST and walks the stages for `bool(<x>.get("<literal>"))` — and since 0.1.6 finds none: the NOUMENO's `changed`, the one declared hit, reads through `verdict.read_boolean` (the value half of `read_verdict`, which is expressed over it, for a stage whose own parser already decoded the reply). An unreadable `changed` is `False`, the value an absent key always had, with a `WARNING` naming the read; the measured drift still overrides it. The NER's three booleans keep their tolerant coercion (a signal with fallbacks; `"false"` already reads `False`). No prompt moved (68 renderings digest-identical before and after).
- Deterministic utils (pure): `strip_cot` (`<think>`/`<thinking>`), `detect_adjustments` (tone hints from sentiment/intent/emotional_override/pii_risk **+ a `register:*` hint from `parole` via `_parole_to_register`** — a formality axis distinct from sentiment's *emotional* tone; `MIXED`/`None` → no hint). `_blocked_response` (PII-CRITICAL → host `block_message` + core fallback). **No Embedder** (synthesis drift is lexical word-overlap, not embedding).
- **Tokens** like the other stages, per-call with distinct labels (`superego_scope`/`superego_judge`/`superego_voice`): the final `voice` → `ctx.superego_result` → `superego_metrics` (folded into totals); the host accumulates `scope` + each `judge` attempt + EGO retries into `ctx.retry_metrics`.
- **Handoff/early-exit:** closed `vocab.VALID_STOP_REASONS` — **the module is the enumeration; this line does not copy it**, because the copy rotted twice (it was missing `needs_clarification` before `judge_exhausted` was even added). The one distinction worth naming here, because a host that merges the two deletes correct answers: **`judge_exhausted`** is a fact about US (the EGO⇄SUPEREGO correction budget ran out and nothing was committed — very often over a complete, correct reply the judge would not sign) and nobody should count it; **`needs_clarification`** is a fact about the CONTACT (the reply ends by asking them something their own unresolvable request forced) and is the only one a clarification cap may count + `ctx.needs_handoff` signal — the core **signals**, the host **escalates** (retry exhaustion / confidence floor) and does the actual handoff. **Out of scope (outside this library):** the retry LOOP (`cogno-soma` runs it) and its budget `max_corrections` (the host sets it); and, for the host: persona scope/limits/voice prompt text, billing, the real human handoff, semantic cache, which conversation a message belongs to. The full map is `docs/ARCHITECTURE.md`.
