# SUPEREGO — the scope guard and «did you mean…?»

Moved verbatim from `CLAUDE.md` on 2026-11-08: the contract did not change. `CLAUDE.md` keeps a short summary and points here. Update this file in the same pull request as any change to the scope guard or the scope options, as `CLAUDE.md` used to be updated.

- `check_input_scope(ctx, backend, *, scope_prompt) -> ScopeCheckResult` — pre-EGO cheap ALLOW/BLOCK relevance guard; NER-assisted bypass for SOCIAL/CLARIFICATION (no LLM call); **fail-OPEN** (a cost guard must never refuse a legit user on error); the `refusal_message` is generated in the same call. **It now records what it was ASKED** (`ScopeCheckResult.prompt_blocks`, from the closed `_SCOPE_BLOCKS` — the third table of the `voice_prompt_inventory` family, same closed-alphabet guarantee, which matters MORE here because every block of this prompt is written by somebody else: the tenant's rules and the contact's own sentence, quoted verbatim). This is the only stage that ends a turn by itself, so a turn it blocks leaves `ego.ran=false`, `judge=null`, an empty voice inventory and a canned refusal that reads the same whatever the cause. Measured 2026-09-17: a GUEST asking «que materiais posso usar para estudar?» was refused on a turn whose persona held the tool whose entire job is that question, and four readings fit every byte of the trace — the path never appended the tool table, the dispatcher probe answered empty, the identity's RBAC emptied it, or all of it arrived and the classifier blocked anyway. The first three are WIRING and the last is the PROMPT, which is the same split `judge_prompt_inventory` exists for and the one this repo has already paid for reading backwards. A `tool_table` row settles it. **The table is HOST-rendered and the header is CORE-owned** (`SCOPE_TOOL_TABLE_HEADER`, exported): the guard takes a `scope_prompt` string and no dispatcher, so only the host can name the tools — but a host spelling its own header would render a section the inventory cannot see, which is the silent under-report the record exists to end. **Rendered-empty is not absent**: the inventory keys on the HEADER, so a table naming no tool is a short row and a table nobody appended is no row at all (the precedent is the judge's consult block, where "there was no second executor" had to stop rendering like "the second executor returned nothing"). Empty `prompt_blocks` means NO PROMPT WAS BUILT — a bypass — never "a prompt with no sections"; the fail-OPEN error path records like every other, because "the call blew up" and "the classifier read this and allowed" both come back `blocked=False`. Carried to the trace on `ctx.metadata[mk.SCOPE_PROMPT_BLOCKS]` as well as on the result, because the orchestrator consumes the `ScopeCheckResult` and drops it — a PER-TURN fact a carrier must never hold over (soma's `SessionRunner` carries a whitelist and this key is not on it). `test_scope_blocks_sync.py` pins the duplicated table in both directions. **And the digest of the WHOLE prompt it sent** (`ScopeCheckResult.prompt_sha`, also on `ctx.metadata[mk.SCOPE_PROMPT_SHA]`, through `prompts.prompt_digest` — the one digest algorithm in the ecosystem — over `_SCOPE_SYSTEM` then the user half, i.e. exactly the two arguments handed to `backend.generate`): the inventory says WHICH sections rendered and how long each was, this says whether the bytes were the same ones, and a host CANNOT answer that for itself — it digests the slot it writes, and the decision rule, layout, task and examples around that slot are assembled here and never leave the function. That is how a slot proven identical by digest sat under a classifier that flipped. **Only the digest leaves, never a byte of the prompt** (the same reason `mk.PROMPT_SHAS` digests the TEMPLATE and not the rendering), and because the contact's sentence is inside it, it is a **per-TURN** label: it groups repeats of the SAME question — what an A/B over one fixed sentence needs — and is not a deployment-level one (`StageMetrics.prompt_sha` stays that). `None`/absent means NO PROMPT WAS BUILT, the rule empty `prompt_blocks` already carries; the key is POPPED on a bypass so a carrier cannot make a turn that sent nothing wear an earlier turn's digest, and the fail-OPEN path records its digest like every other. `test_scope_prompt_sha.py` pins the identity (the bytes SENT, not the slot), the sensitivity of every row of `_SCOPE_BLOCKS` enumerated from the table, and the canary with its control.
- **"Did you mean…?" on a REFUSED turn (2026-09-30, `cogno_anima.stages.scope_options`)** — not a `SuperegoStage` method (no protocol a host double implements moves): `select_scope_options(ctx, backend, *, options)`, called by the ORCHESTRATOR only after the guard BLOCKED and only when the host injected a selector backend and a closed list (the section titles this reader may read + the capability names on the turn's table). One strict call sorts at most 2 options into `covered` (the very thing asked → the refusal was FALSE → the orchestrator LETS THE TURN THROUGH, never a question: a false refusal answered with options hides the defect — downstream, 5 of the 6 real refusals on which a strict selector found anything were exactly that) and `suggested` (a neighbouring thing → the host may render the closed question «Não encontrei X. Você quis dizer: A / B?»; this module renders nothing a contact reads). **`covered` wins over every `suggested`.** **And `covered` needs EVIDENCE in the code, not only the model's word (2026-09-30):** this PR's own nightly (qwen3:8b) answered «the Wi-Fi password» `covered: ['consult_documents']` 3/3, i.e. a local model lifts the negative. So a covered pick counts only when it shares ≥1 non-generic term with the message (`has_evidence`: `cogno_engram.lexical.terms` — the ecosystem's one tokenizer, imported lazily and fail-CLOSED without it — cut to `EVIDENCE_PREFIX = 6`, minus the frame words of `GENERIC_SUBJECT_WORDS`: school/class/students/… never count, nor the verbs a contact asks with — «sabe», «conhece», «fala» and the forms whose 6-prefix the list did not already cover (2026-10-06, 0.1.1; the inverse heading rescue in `cogno-cortex` reads the same constant and prefix; «conhecimento» shares «conhece»'s cut, a declared cost). Whole words were measured and refused: over the six labelled real 1a downstream the question shares a whole word with its target in 2/6, a 6-prefix in 4/6. An unsupported covered pick is dropped and counted (`covered_unsupported`), and when none survives the case is the refusal of today — never a question; `suggested` is untouched. The closed alphabet is ENFORCED by the code (`parse_selection`: an option not in the list, after trimming, is discarded and counted — a free selector invented 6 in 15 downstream), and `asked` (the X the host may quote) survives only when it is literally in the contact's message, folded. Never raises; model error / no JSON / the wrong schema → `error`, which every caller treats as `none`: the refusal of today, byte for byte. Its own ledger line (`SELECT_STAGE = "superego_select"`); the record rides `ctx.metadata[mk.SCOPE_OPTIONS_SELECTION]`, a PER-TURN key the orchestrator pops before the guard. The model half (strict prompt, gpt-4o-mini: target in options 11/15, the Wi-Fi password 0 on both profiles) is measured downstream, not here; `tests/unit/test_scope_options.py` pins the parser, the discarding, covered-wins and the negative; `tests/integration/test_scope_options.py` is the model half (the 1a shape comes back `covered` n=3, the Wi-Fi password draws nothing, only listed options come out — point it at `openai:gpt-4o-mini`).
