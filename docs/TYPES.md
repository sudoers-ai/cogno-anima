# The turn predicates and the models (`cogno_anima/types.py`)

Moved verbatim from `CLAUDE.md` on 2026-11-08: the contract did not change. `CLAUDE.md` keeps a short summary and points here. Update this file in the same pull request as any change to `cogno_anima/types.py`, as `CLAUDE.md` used to be updated.

**`committed_this_turn(ctx)` — one definition, one enumeration.** "Did this turn run a mutating tool successfully, on ANY attempt?" It reads the turn's own two execution lists — `ctx.turn_executions` (the accumulator) and `ego_result.tools_executed` (a FLOOR, for a single-shot pipeline), in UNION since #105 and no longer "first non-empty wins" — plus `ctx.consult_result` and `metadata[mk.PRIOR_ATTEMPT_COMMITTED]`. **`consult_result` is the intra-turn CONSULT**: a hub persona asks a specialist mid-turn and consolidates her answer, so the tools SHE ran are this turn's tools, and a predicate blind to them answers "repeating is safe" over a turn that already committed. It enters the walk the whole family shares (`types._any_execution`), so `wrote_for_the_contact` and `write_attempted_this_turn` gained it in the same edit — a source only one of them reads is the defect that walk exists to prevent. It is an `Optional[EgoResult]` and not a list because `None` (**nobody was consulted**) and an empty trace (**a specialist was consulted and executed nothing**) are opposite facts for the judge; the consult is ADDITIVE and stays out of `_any_execution`'s `unreadable` denominator, which asks only whether the turn's OWN record could be read (a second executor's clean trace cannot vouch for a hub record nobody could read, and the union's rule is that a new source can only turn False into True). Cost rides on `retry_metrics`, not on a sixth stage slot. The third exists because the first two live ON the context and can die together: in the host's model-routing fallback, attempt 1 commits and a LATER stage raises, and the exception takes the context and its record with it, so the retry is a fresh turn where the write is nowhere. There only the host knows, so it declares — TRUE-only, and the declaration ADDS to what the trace shows, never replaces it. **Who calls it is enumerated ONCE, in the `committed_this_turn` docstring** (`cogno_anima/types.py`) — count, files and functions. This file used to repeat that list and `metakeys.py` repeated it again; four consecutive PRs (#115–#118) each corrected the NUMBER in the copies and each left a stale sub-count or a missing name behind, because a test can pin a token and cannot read two hundred words of prose. The copies are now pointers, and `cogno-host` asserts that every calling function is NAMED in that one docstring. **Why it matters here:** a rule each consumer re-derives is a rule each consumer gets wrong alone — that is what the third source exists to prevent, and what the two VOICE policies proved by arriving already re-deriving it (they read `ego_result.has_side_effects`, the SURVIVING attempt, so a turn that booked, was judge-rejected and re-voiced without tools reported "nothing was written" about a turn that wrote). The last layer that re-derived it closed on 2026-08-25: the offline promise auditor now reads the `trace["guards"]["committed"]` stamp — which the host writes by CALLING this predicate — in union with the execution lists, which stay as a FLOOR because a degraded readout stamps `False` and the declaration is TRUE-only.

**`source_reads_not_called(ctx)` — the read nobody made (2026-09-29).** Which of the host-DECLARED source reads (`mk.SOURCE_READS`, a collection of tool names read from the host's catalog and never guessed from a name) the rejected pass was OFFERED (`ego_result.tools_offered`) and that NO execution record of the turn called, over the shared walk (`types._any_execution`, the consult included). It is the fifth member of that family, and `test_consult_is_the_second_source.py` derived it from the AST before it was added. Its consumer is cogno-soma's `_owes_a_read`, the sibling of `_owes_an_action`: a rejected INFORMATION_REQUEST whose draft asserts ABSENCE over a source that was on the table and never read gets ONE more executor pass, because the voice cannot read and re-voicing ships the same false negative. The shape it exists for was measured on a rehearsal tenant: the document read was offered, only an empty ledger summary was called, and the reply said "there are no records" over documents that held the values. Three choices are pinned in `tests/unit/test_source_reads_not_called.py`:
- **ALL OR NOTHING on the called side.** Any declared source read called on any pass makes the answer `[]`, and a read that failed or found nothing was still made, so "nothing relevant" stays a true negative.
- **It leans towards "called".** An unreadable carrier answers `[]`, so the consumer leaves the turn at one pass.
- **Absent or garbled declaration → `[]`.** That is the off switch; a bare `str` is one name.

### Models (`cogno_anima/types.py`)

All cross-stage data is `pydantic.BaseModel`. Key types: `StageMetrics` (per-call telemetry; carries LLM `tokens_in`/`tokens_out` **and** `embedding_tokens`/`embedding_calls` **and** `cached_tokens`; `tokens_total` auto-computed in `model_post_init` as `tokens_in + tokens_out + embedding_tokens` — `cached_tokens` is deliberately absent from that sum, being the SUBSET of `tokens_in` the provider served from its own prompt cache, read through `cogno_synapse.cached_tokens_of` immediately after the `await` that produced the call and summed on the same axis as the tokens beside it: per attempt in NOUMENO/NER, per step in the EGO loop, per call in the SUPEREGO. A backend that reports nothing gives 0, which downstream is the FULL input rate — today's behaviour — **and `system_fingerprint`/`served_model`**, the provider's own answer to *who* served the call: the backend configuration's fingerprint and the dated snapshot an alias resolved to, read through `cogno_synapse.system_fingerprint_of`/`served_model_of` immediately after the same `await`. Not counts and never in `tokens_total` — the only operation ever performed on them is a COMPARISON between two calls, which is why a blank is normalised to `None` (two `""` comparing equal would assert an agreement nobody expressed) and why they are NOT summed: **several calls, one row → LAST CALL WINS**, `None` included when the last call reported nothing, rather than a list that inflates every row. Measured on a downstream host: the same scope-guard input classified ALLOW 4/4 and, forty-five minutes later, BLOCK 7/7 at `temperature=0` — stable inside each period, across process restarts of the SAME build, with the host-written prompt slot proven byte-identical by digest — and nothing persisted could say whether the same backend had answered. The scope guard, where that was measured, makes exactly ONE call per turn, and the correction loop already gives one row per attempt), `NoumenoResult`, `IntentResult` (with helper methods `aristo_tag`/`aristo_desc`/`aristo_parsed` for parsing `"TAG | description"`-style aristotelian fields), `IdResult` (ID routing/continuity output: `triad_route`, `active_goal`, `goal_status`, `goal_similarity`, `active_intentions`, `attention_focus`, `blocked`/`block_reason`, `turn_number`, `temporal_class`, `emotional_override`, `complexity`, `metrics`), `DriftMetrics`, and `PipelineContext` (the carrier — `noumeno`/`intent`/`id_result`/`ego_result`/`consult_result`/`drift` — with derived properties `total_tokens` (incl. embeddings), `total_llm_tokens`, `total_embedding_tokens`, `total_elapsed_ms`, `stage_metrics`, and per-stage `noumeno_metrics`/`ner_metrics`/`id_metrics`). NOUMENO records embedding cost from its similarity calls; NER records its LLM generate tokens; ID records embedding cost from goal similarity (no LLM tokens).
