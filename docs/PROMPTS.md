# Prompt order and the provider's prompt cache

Moved verbatim from `CLAUDE.md` on 2026-11-08: the contract did not change. `CLAUDE.md` keeps a short summary and points here. Update this file in the same pull request as any change to the order of a prompt's blocks, as `CLAUDE.md` used to be updated.

**Prompt ORDER is the provider's prompt cache (F1.3, 2026-09-24).** A provider reuses only an IDENTICAL PREFIX (OpenAI: from 1024 tokens), so within every prompt the blocks run from the most STABLE to the most VARIABLE: the stage's fixed instruction, then the persona's text and rules, then the tool catalogue, then memory and session context, then the date, the time and the turn's own message. Measured per stage, deterministically, over a host's six personas and two consecutive turns of one contact (o200k): **NOUMENO** (1468 tokens) and **NER** (3114) already share their whole static system prompt and nothing moved; the **scope guard** is under 600 tokens in total and its pending-request block is FIRST by a measured rule (#181), so it did not move either. The **judge** is the one this repo reorders: `_build_judge_prompt` opens its user half with `# Persona limits` (the only section that belongs to the persona and not to the turn), and every other section keeps its relative order and its bytes. The shared prefix goes from 36 tokens to 440–1852 tokens once the host puts its `[AMBIENTE]` block (which carries the minute) at the END of the limits slot. **What was NOT moved, and why:** the judge's criteria and the fixed rules after them are its largest stable text, but they say "above" about sections the turn fills ("the Context above", "marked OK above", "a tool result above"). Moving them first changes TEXT, not order, so it is left for its own A/B. The **EGO** and the **voice** gain nothing from a reorder here: everything this repo appends (task context, `mk.EGO_CONTEXT`, the actions block, the whole voice user half) comes AFTER the host's slot, which ends with the minute. Their prefix is the host's to extend (`cogno-host` appends the environment block last, after the capabilities: EGO 55 → 467–4202 tokens, voice 55 → 353–1919). **The gain is a measured PREFIX, not a cache rate**: whether a provider then serves those bytes from its cache also depends on its time-to-live (OpenAI: minutes of inactivity) and on how the traffic falls inside it, so the real cached rate is a number only a ledger gives. It is a PROMPT change all the same: where a rule sits can move what a model does with it, and that half is an A/B. `tests/unit/test_judge_prompt_cache_order.py` pins the twin (≥ 1024 by the whitespace-word lower bound), the control (no limits slot → the legacy order and bytes), the per-section digest multiset, the legacy reconstruction against `origin/main`'s own digests (`_ORIGIN_MAIN` — a landing-time proof, regenerated when the judge's text changes deliberately), the mutation written as a twin, and the sentences that place the limits "above".
